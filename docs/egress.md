# Outbound connection boundary

Page and robots requests use the same HTTP client. On each new TCP connection its dial hook resolves the original hostname once with `LookupNetIP("ip", host)`, checks every returned IPv4/IPv6 address, then passes only a numeric IP and numeric port to `net.Dialer`. Literal addresses skip DNS. IPv4-mapped IPv6 addresses are unmapped before classification and dialing; scoped addresses are rejected. No hostname is passed to the final dial, so a second DNS answer cannot replace the checked destination.

An empty result, more than sixteen addresses, any denied address in a mixed answer, or any resolution error rejects the entire connection before a dial. Multiple permitted answers are tried sequentially within one shared five-second DNS/connect deadline. The existing five-second HTTP request timeout also applies. Serial fallback can reduce availability when an early address is slow; there is no Happy Eyeballs implementation here. DNS failures and denied destinations use the existing bounded durable retry path. A denied robots fetch caches a restrictive ten-second error and fetches no page, with the normal three-attempt terminal boundary.

The conservative address policy rejects IPv4 private, loopback, link-local, shared carrier-grade NAT, documentation, benchmark, multicast, reserved and other special-purpose ranges. IPv6 must fall within `2000::/3`, excluding the IETF assignment block `2001::/23`, documentation, 6to4 and AS112 special prefixes. This also excludes IPv6 loopback, unique-local, link-local, multicast, NAT64 translation and unallocated/nonstandard ranges. Some globally reachable special-purpose addresses are deliberately denied rather than implementing all registry exceptions.

The static ranges were checked against the [IANA IPv4](https://www.iana.org/assignments/iana-ipv4-special-registry/) and [IPv6 special-purpose registries](https://www.iana.org/assignments/iana-ipv6-special-registry/) on October 26, 2026. They are not automatically refreshed. The [Go transport contract](https://pkg.go.dev/net/http#Transport) routes normal HTTPS connections through the TCP dial hook before TLS; the [resolver contract](https://pkg.go.dev/net#Resolver.LookupNetIP) supplies IP results. The URL, HTTP Host and TLS server name remain the original hostname, and ordinary certificate verification remains enabled. Proxies and redirects remain disabled. A pooled connection retains its previously checked numeric endpoint; a new connection performs a fresh lookup/check. This does not re-resolve DNS on every request or cut off an existing connection when DNS changes.

## Controlled fixture exception

Default workers have no local-network exception. Compose and the local Kubernetes overlay explicitly set `CONTROLLED_FIXTURE_ORIGIN=http://fixture:8081`. The worker accepts this mode only when that exact origin is its only allowed origin. The fixture client rejects other schemes, hosts and ports before transport and permits only RFC1918 IPv4 or IPv6 unique-local answers for `fixture:8081`. It still rejects loopback, link-local/metadata, public and mixed denied answers. It grants access to this named fixture endpoint within those private ranges, not to a cryptographically authenticated container identity. Operators must control the local fixture DNS/network; this mode must not be used for public targets. No arbitrary CIDR or host bypass setting is exposed. Test-only constructors grant exact loopback endpoints for local HTTP fixtures.

```sh
python scripts/egress_smoke.py
```

This creates its own Compose network, database volume, two workers and random loopback API/fixture ports. The allowed fixture hostname first resolves to a private container address with its exception disabled: the job queues a policy error and the fixture must record zero robots/page requests, with no document/search result. Enabling the explicit fixture mode recreates the workers; the same durable job must complete on attempt two after the normal cache/retry delay, with exactly one policy and one page request and one admitted URL. The harness removes only its owned stack/volume. Its report/log include source revision, dirty-tree boundary and cleanup result. CI retains these as `egress-smoke` alongside the robots, admission and Kubernetes scenarios.

Deterministic Go tests inject resolver answers and a final dial function. They check private/mapped/scoped/literal/mixed answers, DNS changes between new connections, numeric fallback and deadlines without connecting to public IPs. A local TLS server receives the original Host and server name through a synthetic public-address dial mapping; trusted certificates pass and untrusted certificates fail. Changing the injected answer to loopback then prevents both page and robots dials. Other local tests exercise default loopback denial and unchanged redirect/body/policy rules. These test mappings are not runtime configuration.

## Limits

This is one application-layer SSRF boundary for a controlled-origin crawler, not a complete production security guarantee. It does not authenticate DNS, establish how the operating system routes a permitted public address, inspect NAT/proxy infrastructure beyond the disabled application proxy, or protect against a compromised runtime. Resolver traffic itself follows the host's resolver configuration. Network-layer egress restrictions remain a deployment requirement. Existing index contents are not purged, and API authentication, per-client quotas, automatic recrawl scheduling and production operations remain unimplemented. No public-web crawl, performance claim or GCP deployment follows from this verification.
